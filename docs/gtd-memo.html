GTD-памятка · твой трекер задач

Следующее действие

Главный экран должен показывать не проект, а ближайший физический шаг. Всё остальное — механика того, как этот шаг вычислить, показать и передать эстафету дальше.

1

Проект ≠ действие

Проект — любой результат, требующий больше одного шага. Действие — конкретный физический шаг, начинающийся с глагола. В GTD рабочий список состоит из действий; проекты живут отдельно и нужны для обзора, а не для ежедневной работы.

«Получить ПМЖ в Швеции» — это проект. На трекере вместо него должна светиться строка «Заполнить заявление» — первое доступное действие.

2

Первое доступное действие

Из всех подзадач ровно одна (или несколько) — «делай сейчас». Остальные либо сделаны, либо ждут своей очереди, либо ждут другого человека. Именно доступное действие выносится на карточку — крупно, с его собственным сроком.

Как выбирается «доступное» — зависит от режима подзадач ⤵

3

Последовательные и параллельные

Различие из OmniFocus — самое прямое решение твоих двух сценариев.

▸ Sequential

Строгий порядок. Доступен только первый незавершённый шаг.

✓ Написать ТЗ
→ Согласовать ТЗдоступно
⏸ Поставить в разработкуждёт очереди

⇉ Parallel

Любой порядок. Доступны все шаги сразу.

→ Заполнить заявлениедоступно
⏳ Согласовать с профсоюзомждём ответа
→ Подобрать страховкидоступно
доступно — делай сейчас ждёт предыдущего (порядок) Waiting — ждём человека сделано
4

Waiting For — не «висит», а «ждёт»

«Согласовать с профсоюзом» — это не твоё действие: ты ждёшь другого человека. Такой шаг не должен мельтешить среди доступных, но и теряться не должен. В GTD это отдельный список @Waiting For.

В твоей схеме статус blocked уже есть — задействуй его как «ожидание» + поле waitingOn (кого ждём). Отдельный фильтр ⏳ Waiting — и «зависших сто лет» дел больше нет: они честно помечены как ожидание.

5

«А что дальше?» — эстафета

Иногда следующий шаг рождается только в момент завершения предыдущего. Два случая:

Цепочка известна заранее — «ТЗ → согласовать → в разработку». Просто заводи sequential-подзадачи сразу; всплывать будут по одной.

Шаг ясен только в конце — «прочла письмо из школы → теперь понятно, что надо готовить форму». Ритуал GTD: завершая шаг, спроси «а какой теперь следующий?» и запиши. В UI — мягкий промпт «Следующее действие?» при закрытии.

6

Еженедельный обзор

Механика осыпается без гигиены. Раз в неделю — пройтись по проектам и проверить один инвариант: у каждого активного проекта есть живое доступное действие? Если нет — оно либо в Waiting, либо в «когда-нибудь», либо надо придумать next action. Именно обзор ловит зависшие дела.

Одной фразой. Проблема не в механике, а в том, что на рабочем экране лежат проекты. Показывай первое доступное действие вместо названия проекта, добавь режим sequential/parallel для подзадач и используй blocked как Waiting For — и все три боли закрываются одним ядром.
